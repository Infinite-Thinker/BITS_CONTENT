What is a Convolutional Neural Network?
Definition
A Convolutional Neural Network (CNN) is a specialized type of deep neural network
designed to process data with a grid-like topology, such as images, where spatial
relationships between data points are important.
Core Insight
CNNs mimic the visual cortex by detecting simple patterns (edges, corners) in early
layers and combining them into complex objects (faces, cars) in deeper layers.

Why Convolutional Networks?
Why CNNs for Images?
Translation Invariance: Object recognition regardless of position
Local Patterns: Detect edges, textures, and shapes locally
Hierarchical Features: Low-level  Mid-level  High-level features
Parameter Efﬁciency: Fewer parameters than fully connected networks
Computational Efﬁciency: Parallel processing of convolutions

Key Principles of CNNs
Three Key Principles
1 Local Connectivity (Sparse Interactions)
▶ Each neuron connects only to a local region of the input
▶ Receptive ﬁeld concept
2 Parameter Sharing
▶ Same ﬁlter/kernel used across entire input
▶ Dramatically reduces parameters
3 Equivariant Representations
▶ If input shifts, output shifts correspondingly
▶ Built-in translation equivariance

=== PAGE 35 ===
The Classification Process
1 Feature Extraction: Convolutional layers progressively extract features of
increasing complexity
2 Spatial Reduction: Pooling layers reduce spatial dimensions while preserving
important information
3 Feature Combination: Deeper layers combine simpler features to recognize
complex patterns
4 Decision Making: Fully connected layers use extracted features to make ﬁnal
classiﬁcation decision
5 Output: Softmax layer produces probability distribution over classes
Key Insight
Each layer acts as a feature detector that becomes increasingly sophisticated.
Early layers detect simple patterns, while later layers detect complex objects by
combining simpler patterns.

What is a Feature Map?
Definition
A feature map (or activation map) is the output produced when a convolutional ﬁlter
is applied to an input image or previous layer’s output.
Key Concepts:
▶ Each ﬁlter detects a speciﬁc pattern (edges, textures, shapes)
▶ Output of convolution = feature map showing where pattern was detected
▶ High values in feature map = strong pattern presence
▶ Low values = weak or absent pattern

=== PAGE 50 ===
Receptive Field: Definition
Definition
The receptive ﬁeld of a neuron is the region in the input image that affects that
neuron’s activation value.
Key Concepts:
▶ Receptive ﬁeld grows with network depth
▶ Early layers: small receptive ﬁelds (local patterns)
▶ Deep layers: large receptive ﬁelds (global context)
▶ Determined by kernel size, stride, and pooling
Importance:
▶ Small receptive ﬁeld: Cannot capture large objects
▶ Large receptive ﬁeld: Better context understanding
▶ Trade-off: Computational cost vs. context

Padding
Why Padding?
Without padding: Output size = Input size - Kernel size + 1
Information at borders gets less attention
Deep networks would shrink feature maps rapidly
Types of Padding
Valid Padding: No padding (output smaller than input)
Same Padding: Pad to keep output size = input size
Full Padding: Maximum padding
Same Padding Calculation
For kernel size k and stride s = 1: Padding = (k− 1)/2

Stride determines how much the kernel moves at each step.
Stride = 1: Move kernel one pixel at a time (standard)
Stride = 2: Move kernel two pixels at a time (downsampling)
Stride> 1: Reduces output size, acts as downsampling

=== PAGE 63 ===
Dilated (Atrous) Convolution
Definition
Dilated convolution (also called atrous convolution) inserts spaces (holes) between
kernel elements to increase receptive ﬁeld without increasing parameters.
Dilation rate r: Number of pixels between kernel elements
r = 1: Standard convolution (no dilation)
r = 2: One pixel gap between kernel elements
r = 3: Two pixel gaps between elements
Effective receptive ﬁeld:
keff = k + (k− 1)(r− 1)
where k = kernel size, r = dilation rate
Example: 3× 3 kernel with r = 2  effective 5× 5 receptive ﬁeld

=== PAGE 65 ===
Dilated Convolution: Applications and Benefits
When to Use Dilated Convolutions:
▶ Semantic segmentation: Need large receptive ﬁeld while maintaining resolution
▶ Dense prediction tasks: Object detection, depth estimation
▶ Audio processing: WaveNet uses dilated convolutions for sequence modeling
Beneﬁts:
1 Larger receptive ﬁeld without pooling or striding
2 Preserve spatial resolution (no downsampling)
3 Same parameter count as standard convolution
4 Multi-scale context by using different dilation rates
Trade-offs:
▶ May lose ﬁne-grained local information
▶ Gridding artifacts possible (mitigated with varying dilation rates)
▶ Slightly more memory usage during forward pass

Inception Module: Computational Savings
Without 1×1 reduction (naive):
▶ 3×3 conv: 28× 28× 256× 128× 3× 3≈ 230M ops
▶ 5×5 conv: 28× 28× 256× 32× 5× 5≈ 160M ops
▶ Total:∼390M operations
With 1×1 reduction:
▶ 1×1 reduce: 28× 28× 256× 96× 1× 1≈ 19M ops
▶ 3×3 conv: 28× 28× 96× 128× 3× 3≈ 86M ops
▶ 1×1 reduce: 28× 28× 256× 16× 1× 1≈ 3M ops
▶ 5×5 conv: 28× 28× 16× 32× 5× 5≈ 10M ops
▶ Total:∼118M operations
Result: 3.3× reduction in computation! This is the bottleneck principle that
became standard in deep networks.

Inception Module: Design Philosophy
Why does Inception work so well?
1 Multi-scale feature extraction
▶ Different ﬁlters capture different scales
▶ Network learns which scale is important per layer
2 Sparse connections
▶ Not all inputs connected to all outputs
▶ Mimics biological neural networks
3 Efﬁcient computation
▶ 1×1 bottlenecks reduce dimensions
▶ Much fewer parameters than VGG
4 Increased network depth and width
▶ Can go deeper without computational explosion
▶ Multiple paths increase model capacity
Auxiliary Classiﬁers: GoogLeNet added intermediate classiﬁers during training to
combat vanishing gradients (removed at test time)

Why Do Residual Connections Work?
Multiple explanations:
1 Gradient Flow
▶ Skip connections create ”gradient highways”
▶ Backprop: ∂L
∂x = ∂L
∂y· (1 + ∂F
∂x )
▶ Gradient always has direct path (the ”1” term)
2 Ensemble Behavior
▶ Network behaves like ensemble of shallow networks
▶ Each path through skip connections = different network
▶ 2n implicit paths in n-block network
3 Feature Reuse
▶ Earlier features directly accessible to later layers
▶ No information bottleneck
▶ Layers can reﬁne features instead of recreating them

ResNet: Key Takeaways
Revolutionary Impact ResNet enabled training of networks with 100+ layers, winning
ImageNet 2015 with 3.6% error (superhuman performance on ImageNet!)
Core Contributions:
1 Residual Learning: Learn F (x) = H(x)− x instead of H(x)
2 Skip Connections: Identity shortcuts for gradient ﬂow
3 Very Deep Networks: 50-152 layers trainable (even 1000+ demonstrated)
4 Bottleneck Design: Efﬁcient deep networks using 1×1 convolutions
Impact on Field:
Skip connections now standard in almost all architectures
DenseNet, U-Net, EfﬁcientNet all use residual-style connections
Transfer learning: ResNet features widely used as backbones
Enabled modern very deep networks (Transformers also use residuals!)

Transfer Learning Concept
Definition
Using a pre-trained model on one task as the starting point for a related task
Why Transfer Learning?
Limited Data: Small datasets beneﬁt from pre-trained features
Computational Efﬁciency: Avoid training from scratch
Better Performance: Often achieves better results
Feature Reusability: Low-level features are transferable
Common Scenario
Source Task: ImageNet classiﬁcation (1.2M images, 1000 classes)
Target Task: Y our speciﬁc classiﬁcation problem
Assumption: Similar low-level visual features

=== PAGE 140 ===
Transfer Learning Strategies
Strategy 1: Feature Extraction
Freeze pre-trained layers
Train only classiﬁer (ﬁnal layer)
Use when: Small dataset, similar to pre-trained data
Strategy 2: Fine-tuning
Initialize with pre-trained weights
Train entire network with low learning rate
Use when: Medium dataset, somewhat similar data
Strategy 3: Selective Fine-tuning
Freeze early layers, ﬁne-tune later layers
Balance between feature extraction and ﬁne-tuning
Use when: Medium dataset, different but related data

=== PAGE 149 ===
Common Pitfalls and Solutions
Overﬁtting
▶ Symptoms: High training accuracy, poor validation accuracy
▶ Solutions: More data, data augmentation, dropout, L2 regularization
Underﬁtting
▶ Symptoms: Poor performance on both training and validation
▶ Solutions: Larger model, more training time, lower regularization
Vanishing/Exploding Gradients
▶ Solutions: Proper initialization, batch normalization, residual connections
Computational Efﬁciency
▶ Use appropriate batch sizes
▶ Mixed precision training
▶ Model compression techniques
